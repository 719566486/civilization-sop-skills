# SOP 1 · 文明创作总设定

把一句话发展成可交给美术和视频制作的三份主交付。用户的新要求与已有授权优先于本技能默认值。先读取项目约定与有效版本，不把旧稿、废弃素材或别的文明风格当作当前事实。

## 命名与开发登记边界

执行前读取 [美术命名规则](references/art_naming.md)。正式美术文件统一snake_case，源文件/交付历史使用rNNN，运行时文件保持稳定名称；Asset ID、Asset Key、最终Runtime Path与正式Manifest由开发管理。制作passed不等于运行时发布批准。

## 逐步操作手册

执行前读取 [操作手册 1.3](references/operations-manual.md)。其中逐步列出工具、输入输出格式、参数与提示词、合格标准、失败返工、命名版本和单节点资产清单；本页提供流程入口，具体执行以手册和交接契约配合使用。

## 执行

1. 读取用户文明想法、已有资料与可复用角色/飞行器参考。建立来源表：有效、历史、冲突、缺失。选择明确标记的最终稿；仅凭文件日期不能判定内容正确。存在影响角色身份的冲突才询问，其他创作空白自主填写并标为创作设定。
2. 用户只有一句话也启动写作。默认规划一条完整探索弧，按文明复杂度安排章节；建议初稿 5–7 章，每章 1–3 个 15–20 秒视频单元，用户可改数量、语言与比例。不要把 Alpha 的七日结构当所有文明的定律。自动填写不等于授权收费生成。
3. 读取 [创作标准](references/creative-standard.md) 与 [交接契约](references/handoff-contract.md)。先建立文明运作逻辑，再写 Traveller 的目标、阻力、证据和选择，最后反向核对资产是否覆盖每个镜头。
4. 输出 `01_world.md`，达到可回答日常生活、资源流动、权力运行、历史变迁、环境危险和可见建筑细节的具体程度。每条核心世界规则至少落到一处剧情证据或美术设计，不以大段百科名词充数。
5. 输出 `02_story.md`，同时给完整故事和逐镜执行表。把结局需要的证据提前放入行动。每段最终时长 15–20 秒，分镜给精确起止、动作、机位、声音及入/出状态；复杂交接或大幅视角改变拆镜，保持时间总和正确。
6. 输出 `03_design_atlas.md` 和 `reference/`。先锁定实际可读的 Traveller、飞行器等 global 参考；没有旧图时说明缺失并建立明确标识的新基线，不能声称沿用了不存在的资产。每个新文明角色、关键物件和反复出现的地点均生成设定图。角色给轮廓、服装、正侧背或必要的可见角度；载具给结构多视图和尺度；地点给空间总览、结构关系和重复机位的基准。
7. 设定图使用可用的 Codex 内置 imagegen，或用户选择且已配置的 Image2 接口。先检查工具与外发/预算授权；参考编辑前查看参考原图，真实附加参考，不只把文件名写进提示词。内置工具遵循当前宿主 schema，不编造端点；第三方 Image2 明确服务商与所需凭据。工具缺失则继续完成文字部分并标 blocked，不能将提示词当设定图。
8. 查看输出图像后锁定母图版本。图册内嵌真实图片相对链接，登记源图、身份特征、可变状态和禁止变化。先母图后多视角，不独立随机重造同一个实体。
9. 写 `handoff.json`。检查剧情因果、知识揭示顺序、空间路线、时间状态、人物与载具比例、每镜资产覆盖。通过检查的包才交给 SOP 2；自动检查通过即可推进已授权内容，不凭本技能另加审批轮次。

## 交付

三份主文档 + 图册所用实际图片 + 交接清单。汇报文明主题、视频单元数量、复用/新增资产和未解决项。仅被请求做文字规划时尊重范围，明确这是准备稿而不是完整图文 SOP 1。

交付同时填写 [节点资产模板](references/node-assets.json) 中每项资产的命名、修订、文件分区、依赖、规格、软件和来源授权。无开发确认时仅交制作包/待登记清单，不向Godot工程导入或自行生成运行时Manifest。
