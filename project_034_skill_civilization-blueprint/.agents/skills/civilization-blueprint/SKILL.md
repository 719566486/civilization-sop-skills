# SOP 1 · 无人前文明遗迹创作

将一句文明想法发展成三份可交接的图文制作文件。用户新的明确要求优先；本项目的固定前提是：探索当下的前文明已废弃，无现存居民，Traveller是外来探索者。玩家根据他传回的资产自行拼凑文明全貌。

## 必须保留的创作边界

- 遗迹当下没有文明居民、幸存者、向导或讲解型NPC，不用能完整回答历史问题的AI、幽灵或交互全息人格替代居民。Traveller及明确授权的外来装备不属于前文明居民。
- 先在创作内部建立庞大、完整、具体的昔日文明，再推导今日遗迹。完整内部设定不等于完整展示给玩家；不要因“无人”把经济、制度、生活史省略成几个废墟名词。
- 剧情采用观察、勘察、对照、取证与传回。Traveller只能报告观测或有依据的推测，不代替玩家得出全部答案；禁止全知旁白、活人讲史或自动播放完整文明复原。
- 持续运转的残余机械可以作为遗留现象，但要有能源来源、寿命和故障边界；灯亮不代表有人住。历史雕像、壁画、有限录音如需使用，只作为残存记录，不演成当下活人。
- 逐节点区分内部真相、Traveller此刻知道的内容、玩家实际收到的资产、可支持的推断与仍未解决的疑点。读取 [遗迹与证据契约](references/ruins-evidence.md)。

## 执行

1. 读取项目约定、有效资料和全局母图，记录有效／历史／冲突／缺失。先前存在居民的稿件与本前提冲突，应列为旧方案，不继续直接派生。
2. 读取 [操作手册1.4](references/operations-manual.md)、[创作标准](references/creative-standard.md)、[交接契约](references/handoff-contract.md) 与 [美术命名规则](references/art_naming.md)。只有一句话也可启动，创作空白自主填写并标为虚构设定。
3. 输出 `01_world.md`：分为“昔日文明／内部真相”“弃置过程与时间”“今日遗迹状态”“证据如何保留下来”。详写原来的资源、权力、生活与风格，并逐项推导留下的空间、磨损、沉积、失效与缺失；本文为author_only。
4. 输出 `02_story.md`：默认规划完整探索弧，可从5–7章、每章1–3个15–20秒节点起步；不固套七日结构。每镜给起止时间、机位、动作、首末状态、实体和证据引用。每个节点传回可见资产，证据先于推断；穿越大空间要标省略，不安排与居民互动或以拯救在住人口为目标。
5. 输出 `03_design_atlas.md` 与实际 `reference/`：复用Traveller、飞行器等有效母图；为当下遗迹、关键物件、铭刻及重复机位建立真实设定图。历史服饰／人物形象仅在壁画等证据确需时设计，标historical_depiction，不默认生成可当场出镜的文明角色。昔日完整复原图默认不生成；确有内部设计必要时标author_only，绝不混入传回资产。
6. 使用已授权且可用的内置imagegen或用户选择的Image2。真实附加已查看母图，先母图后派生；检查空城有没有意外人群、干净使用痕迹、原样完好的盛世或图册标签。不以提示词代替实图，工具受限时交blocked准备稿，不自动扩大收费授权。
7. 编制 `evidence_plan.json`：逐条关联节点、镜头、遗迹痕迹与拟传回的图片／视频任务；写明直接可见事实、支持与不支持的结论。所需文件未生成时使用计划引用，不编造已存在的路径。
8. 写 `handoff.json` 和 [节点资产模板](references/node-assets.json)，携带无人前提与证据边界到SOP2/3。先检查人物缺席、遗弃时间逻辑、证据公平性及剧透，再检查时长、空间、身份与文件。全部必要项通过才放行制作；开发登记继续pending，不自行生成运行时Manifest。

## 三份主交付与附属记录

世界观、探索脚本、实际设定图册为内部制作文件；附实际图片、证据计划、逐节点清单及QA。玩家接收集合由明确的player_transmission白名单决定，默认不包含三份内部文档、答案索引、完整复原图或调试文字。当前阶段只规划的传回图像不算已生成。

正式美术文件仍使用小写snake_case；源文件／历史版本使用独立rNNN，运行时名称稳定；Asset ID、Asset Key、Runtime Path与正式Manifest由开发确认。本次调整不改变已有命名规则。
