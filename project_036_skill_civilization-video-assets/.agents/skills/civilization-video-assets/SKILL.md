# SOP 3 · 文明短视频资产生产

输入 SOP 1 剧情、图册及世界规则，SOP 2 的实际图像与清单。交付单位是每条 15–20 秒 MP4，可以包含数个有因果关系的镜头；不要自动扩成宣传片或一部长片。

## 逐步操作手册

执行前读取 [操作手册 v1.1](references/operations-manual.md)。其中逐步列出工具、输入输出格式、参数与提示词、合格标准、失败返工、命名版本和单节点资产清单；本页提供流程入口，具体执行以手册和交接契约配合使用。

## 先检查环境

读取 [后端与技能检查](references/providers-and-skills.md) 和 [交接契约](references/handoff-contract.md)。依次检查：
- Kling MCP 是否可发现，who_am_i 是否成功；Flova CLI 是否存在、version / auth status 是否成功。对两条路线均给出状态，实际生成只需选中的一条可用。
- 选中后端的账户/项目可访问、可用模型、时长、尺寸、参考图限制、音频和字幕能力；版本帮助与实时 schema 为准。
- 是否具备当前任务需要的编辑能力。字幕/混音/接镜可能需要 FFmpeg，或 HyperFrames 的相关技能；不要求所有可选技能全部安装。
- 用户的既有外发范围、预算、重试次数是否覆盖具体任务。先完成脚本、样帧、逐条任务表和费用条件核实，再为确实未授权的费用询问一次。已有批准继续有效；不得硬编码作者历史账户、积分或预算。

输出 `qa/preflight.md`，分别标已发现、已连接、已登录、已核验、缺失、未测。若选中后端缺失，继续完成可执行任务包，说明阻塞；不偷偷换后端、不自动安装或改账户。

## 生产

1. 校验图像全部为 passed 且版本匹配。逐段写明动作节拍、机位、真实参考对应、入/出状态、对白和声音方案。读 [制作与验收](references/video-production.md)。
2. 优先把目标设计为平台支持的 15 秒完整自然动作，满足 15–20 秒范围。若目标 18–20 秒而单次上限更短，则用兼容模型/有接续的多个原片完成；不得把不支持的 20 秒参数强行提交，不靠重复、慢放或黑屏凑时长。复杂动作减少或拆镜。
3. 通过 Kling 时先使用实时 schema 生成请求，上传工具接受的图片副本，保留母图。首次回执立即保存 generation ID；查询已有任务到终态，下载问题先重下载同任务。
4. 通过 Flova 时优先加载已安装 flova 技能，用同一个已确认项目上传脚本、设定参考和剧情关键帧；确认平台实际读到了材料。发送一条有边界的自然语言任务，使用默认聚合 `flova run` 等待终态，不另写轮询器、不因安静而重复提交。CLI 被宿主转为后台会话时续接原会话。出现 blocking pending action 时遵循当前动作的选项与恢复标识，不猜测批准。
5. 保存原片与任务记录。需要后期时仅按用户要求装配、字幕、声音和自然收束；不把本地静帧运动当成已生成的视频动态。Flova 单独媒体可以直接交付；最终导出片需确认导出任务成功并下载真正成片，不用资源归档包冒充。
6. 测量每个最终 MP4 的实际时长与规格，完整解码，查看各镜头首中尾及所有接点，听辨整条音轨。质量失败只返修相关段，重试费用受原授权约束。未有实际媒体只报告任务包准备完成。
7. 输出 `videos/`、`video_manifest.json`、`qa/video-review.md`。每段达到 15–20 秒且通过完整性、视觉连续性、声音与脚本检查后才 passed；失败项与待确认项如实列出。
